# Inputs, tools and outputs

Every kind of node, and the format the models are saved in. `og nodes` lists them with their settings, and [FORMATS.html](FORMATS.html) the file formats.

## Inputs, tools and outputs

The tools are named by what they do. The second column is the name of the type in
model files, and what `og nodes` lists. Those names are the same as before, so
models from earlier versions open and run as they did.

| Node | In files | Does |
| --- | --- | --- |
| Input | `Reader` | Reads GeoPackage, Shapefile, GeoJSON, FlatGeobuf, SpatiaLite (.sqlite, .db), Excel, LibreOffice Calc, CSV and txt, and JSON without geometry, also zipped and from a web address, and GeoTIFF as points, squares, an outline, an image or a grid of heights, also only within a rectangle, from a Cloud Optimized GeoTIFF on the web without fetching the rest: from its overviews when it is read coarser. Point clouds from laser scanning, LAS and LAZ, a feature for each point with its height, class, intensity, returns and colour: only some classes, every n-th point, within a rectangle. COPC (`.copc.laz`), also on the web, through its octree: only the parts within the rectangle and the levels down to a spacing between the points are read, and from the web only those are fetched. 3D Tiles from a tileset.json on this computer or the web: Batched 3D Models (.b3dm), glTF tiles of 3D Tiles 1.1 with their property tables (EXT_structural_metadata), also compressed with meshopt and quantized as tyler and gltfpack pack them, composites, point clouds (.pnts) and implicit tiling with subtrees, at the coarsest level of detail, the finest or down to an error in metres, within a rectangle, placed in the coordinate system you choose, with the features of each tile and its table of attributes. **CAD drawings as DXF and DWG** (DWG from AutoCAD R13 to 2018 and later is made DXF by acadrust and read as DXF is): a feature for each entity, with its CAD layer, the kind of entity (LINE, LWPOLYLINE, CIRCLE, TEXT, INSERT…), its colour as #rrggbb, line type, line weight and handle, the text, height and angle of texts, and for a block the name, angle and scale and each of its attributes as an attribute of its own (ID, DJUP…). Blocks become points with their attributes, or are drawn out as their lines (*Blocks*); closed polylines, circles and ellipses become areas, or stay lines (*Closed polylines*). The log tells the AutoCAD version, the units, who saved it last and the extent. A DXF does not say its coordinate system, so one is to be given; without it the drawing is read all the same, to be looked at and written, with a warning that suggests one from the coordinates (SWEREF 99 TM, a local zone of SWEREF 99 or RT 90). **GeoParquet** (.parquet), without GDAL: geometry as WKB, its coordinate system from the metadata, compressed with Snappy, Zstandard, gzip, LZ4 or Brotli. **City models** as CityGML 1.0, 2.0 and 3.0 (.gml, .xml) and CityJSON 1.x and 2.0 (.city.json, .json, also CityJSON Sequences, .jsonl), without GDAL: a feature for each city object (building, building part, bridge, tunnel, road, water, vegetation, terrain, furniture…) with its id, type, parent, level of detail, lowest and highest height and height, and its attributes; the outline as the area and the surfaces as a 3D model, coloured by what they are (roofs, walls, ground, windows, doors). *Level of detail* chooses the finest of each object, the coarsest, or LoD 0, 1, 2 or 3. Implicit geometries and templates are placed, and the coordinate system is taken from the file; a city model that does not say one, as the small examples of cityjson.org, is read without one, with a warning and a guess from its coordinates. Buildings from **IFC** (IFC2x3, IFC4, IFC4.3): an element a feature with GlobalId, class, name, description, object type, tag, storey and the height of its floor (`storey_z`, 0.95.2), type and material, and every property set and quantity as an attribute (Pset_WallCommon.IsExternal), and the model for 3D: extruded profiles (rectangles, circles, I, L, U and T sections, polylines and arcs, with holes), faceted breps, advanced breps (faces on planes, cylinders, cones, spheres, tori and B-spline surfaces, also rational, bounded by lines, circles, ellipses and B-spline curves, as Revit and other CAD write curved shapes), surface models, triangulated and polygonal face sets, mapped items, also mirrored and scaled, booleans that take away a half space (also bounded by a polygon, as a roof cuts a gable wall) or another solid, closed where they cut, with the colours of their styles or materials and glass for windows; openings cut out of walls and slabs, also openings that are not boxes, with the reveals in the hole, and taken through their wall when they stop short of its face by up to 10 mm, as openings exported from Revit often do; placed by IfcMapConversion or ePSet_MapConversion in their coordinate system, by the latitude and longitude of the site, or by the origin given. 3D models as OBJ files, with their MTL materials and textures beside them, and as glTF 2.0: .gltf with its buffers and pictures beside it or inside it, or .glb. PNG and JPG with a world file are read as images. OpenStreetMap as .osm.pbf or .osm, a layer at a time (points, lines, multilinestrings, multipolygons, other_relations), with each common tag as an attribute of its own (*Tags as attributes*: the common ones, those on at least one feature in a hundred, at most 100; all; or none). Only the chosen layer is held while the file is read, so a layer such as multilinestrings can be read from a whole country Pictures or grids from a folder of tiles become one. One file, chosen layers of a file, or all files in a folder that match a filter. Can add the file name and the layer name as attributes, and can stop at a number of features. *PostGIS…* beside *File…* and *Folder…* reads from a database instead (below). Web services are read page by page, and only within a rectangle when one is set: OGC API Features (an address with /collections), WFS and ArcGIS FeatureServer or MapServer layers; the program lists their layers. Statistics in JSON-stat, as from Eurostat, become a row per value. An API connection gives the address its key or login. **Vector tiles** (Mapbox Vector Tiles, as MapLibre draws maps from) from .mbtiles, .pmtiles (also on the web, fetched in parts), a folder of tiles or a web address with `{z}/{x}/{y}`: at a zoom level, with the layer of each feature as an attribute, and the pieces the tiles cut a feature into put together again (*Pieces*). A .zip that holds several data files reads the first, or the one in *File in the zip*. **GPS tracks** from .gpx: tracks, routes or waypoints, the first that the file has, or the layer chosen. **Photos** (.jpg without a world file) as points where they were taken, from their Exif: the time, the place and height, the direction the camera looked, the make and model, and the size. **GeoParquet within a rectangle** reads only the row groups whose boxes reach into it, from a file on this computer or from any web address, where only those parts are fetched. **GTFS** timetables from a zip or a folder with stops.txt and trips.txt: the stops, or the layer chosen: routes, trips (each as a line), shapes_geom, stop_times, calendar and the others, in WGS 84. **NetCDF and Zarr** data cubes (.nc, a .zarr folder): each variable on a grid is a layer; as points or squares the steps of time are attributes named after their dates, such as `time_2026_07_01`, and as a grid or a picture one step is read, chosen by its number or its date in *Time step*. Rows that run from south to north are turned. **Point clouds** (LAS, LAZ, COPC) are kept as columns, about 30 bytes a point, so tens of millions can be read; every point is read unless a limit is set, and the tools for point clouds work on them as they are, while other tools get the points as features. **DWG and DXF** give their 3D faces, polyface and polygon meshes, meshes and the flat faces of 3D solids as a 3D model, each body a feature with its layer, kind, colour and handle, to write as glTF, 3D Tiles or CityGML. **With a stream on Paths** (0.94), it reads the file each feature names in an attribute (_file from HTTP request, or a column of a list of files) instead of its own, and the features of each file get the attributes of the row that named it; grids are put together into one. This did the tool *Read files named in an attribute* before, and models that have it open with an Input in its place. **Nautical charts in S-57** (.000, with its updates .001, .002 … applied): every object class as one stream, each feature with its class by its code and by a name to read (DEPARE, Depth area), the soundings as points with their depth; or one class chosen as a layer. **Bathymetry** as BAG and S-102 (.bag, .h5): depth and uncertainty as two named bands of a grid; a grid of several bands keeps them all, with their names. **KMZ** as KML. DWG and DXF also give **the round faces of 3D solids** (cylinders, cones, spheres and tori), **regions and surfaces** as a 3D model; what a drawing has that is not read at all, such as pictures and references to other drawings, is said in the log. *Encoding* also applies to DXF, and text with characters that could not be read (shown as �) is said in the log, with whether another encoding may help. **E57** (0.95), as laser scanners on the ground give them: every scan in the file, placed by its pose, as one point cloud with colours and intensity; every n-th point and a rectangle as for LAS **Google Sheets** (0.96.1) by the address of the sheet: one shared with a link as it is, the sheet in the address (`gid`), and a private one through an API connection with a Google service account that it is shared with, any sheet by its name in *Sheet*. **XML** (0.96.2) as records, as JSON is: the elements that come again, found by themselves or at a path such as Fastigheter.Fastighet, each a feature, with its child elements and XML attributes as attributes, elements within elements as adress.ort, and codes with a leading zero kept as text. **LandXML** (0.96.2): surfaces as a 3D model of triangles, points (CgPoints) with their codes and heights, and alignments as lines with their arcs, each a layer, in the coordinate system the file names. **Gaussian splats** (0.96.2) from PLY, as the training writes them, and SPZ: each splat a point at its middle with its size, turn, opacity and colour, placed on the map by the axis that points up, the metres of a unit, an origin and a turn; a PLY that Ographis wrote comes back in its place by itself. A **PLY of points**, from a scanner or a drone, is read as a point cloud with its colours. Heights as **ASCII grids** (.asc), **SRTM** (.hgt) and **DTED** (.dt0, .dt1, .dt2) (0.96.3). 3D models for **3D printing and CAD**: STL, 3MF with its colours, units and build plate, and STEP where its faces are flat, as from 3D printing and AP242, faceted solids and triangulated surfaces with their colours (0.96.3). |
| Input from PostGIS | `PostgisReader` | Reads tables from PostgreSQL with PostGIS or from Microsoft SQL Server, with their geometry, or what an SQL query gives. A connection of the kind *SQL Server* in the settings goes through ODBC (ODBC Driver 17 or 18), with a user and password or the login of Windows. *PostGIS…* on an Input opens a window where a database connection from the settings is chosen; its tables with geometry are listed at once, and can be searched and ticked, one or many. *Only rows where* sends a condition along, so that the database sends only those rows. Several tables become one stream, with the name of each in the attribute table. *Only within* reads only the features in a rectangle, west, south, east and north in degrees, which can be chosen on the map. *Read a file instead* makes it an Input of files again **Only these columns** (0.96.2): the database sends only the columns named and the geometry, so that a wide table is read faster. |
| Output | `Writer` | Writes GeoPackage, Shapefile, GeoJSON, FlatGeobuf (with a spatial index), Excel, LibreOffice Calc, CSV and txt, and images as PNG, JPG, GeoTIFF and PDF, and the 3D model a stream carries as OBJ (with its .mtl and textures) or glTF (.glb), and **GeoParquet** 1.1 (Zstandard, with a box column for each row that readers skip parts of the file by), and points with heights as a **point cloud**, LAS or LAZ 1.4, with their classes, intensity, returns and colours and the coordinate system. A 3D model is written around an origin near its middle, kept in the file, and is put back in its place when Ographis reads it again, or, with *Origin*, around a point of your own or with its coordinates as they are (`none`), in glTF and OBJ alike; in glTF each object is a node with its attributes as extras. A grid of values, such as from Raster calculator, is written as a GeoTIFF of 32-bit decimal numbers with -9999 where it is empty. A PDF is one page, A0 to A5, Letter, Legal, Tabloid, a size of your own in millimetres or as large as the picture at the pixels to the inch you give, upright or turned, with a margin and a title if you want one, at the left, in the middle or at the right, and with coordinates that GIS programs can read. The picture is packed lossless or as JPEG with a quality, and the log says how large it is printed and at how many pixels to the inch, with a warning and the width to draw it in when that is too coarse for paper. A GeoPackage gets a **primary key**: a new column of numbers by the name you give (fid from the start), or an attribute whose values are all different; whole numbers are the key itself, other values keep fid as the key and get an index that allows each value once. The format is chosen from a list or follows the file name. Can write an attribute as another type, cut text at a length and round to a number of decimals. A workbook gets a font, a bold and a locked top row if you want them (both are off from the start), colours and columns as wide as their contents. Two more formats are in the list: *GeoSpatial PDF with layers* and *PostGIS table* (below). **PMTiles** (.pmtiles): the features cut into vector tiles for the zoom levels chosen and packed into one file, which MapLibre, OpenLayers and Leaflet draw maps from straight off a web server, without a tile server; a layer named as you like. **glTF for Blender**: the objects named by an expression, grouped under a parent for each value of another (as collections are used), materials named by a third (to give all roofs of one kind a new look at once), where the model lies kept for BlenderGIS (the scene properties crs, crs x and crs y), an origin of one's own so that several files fit together, and a sun where it stands at a time and a camera from the south-west if asked. Lines and points without a 3D model are written as glTF lines and points, at their heights. **Cloud Optimized GeoTIFF**: tiled, compressed, with overviews, for pictures and grids that maps on the web read only parts of. **3D Tiles 1.1** (a folder with tileset.json): the 3D model in glTF tiles of at most so many triangles, placed on the globe where it lies, for CesiumJS, Cesium ion, deck.gl and the 3D views of QGIS and ArcGIS; *Height added* lifts it by the height of the geoid, about 20 to 40 m in Sweden, as the globe has heights above the ellipsoid. **CityGML 2.0** (.gml): buildings from Extrude or LoD2 buildings from points, each a bldg:Building with its attributes as generic attributes and its height, in LoD1 as one solid or in LoD2 with ground, walls and roofs told by which way they face. **KML and KMZ** for Google Earth, in WGS 84 degrees, each feature a placemark named by its name attribute, with the others in its data, at their heights when they have them. **GML 3.2**, in the coordinate system of the stream, with its schema in an .xsd beside it. **GPX** for GPS units: points as waypoints and lines as tracks, in degrees, with heights as ele; the attributes GPX knows (name, cmt, desc, src, sym, type, time) in their places and the others in extensions. Areas have no place in GPX and are left out, with a warning. **GeoPackage version** (0.95) 1.2, 1.3 or 1.4 for a new file, for programs that only read older ones. **Pictures** (0.95) keep the pixels to the inch given, for printing, in PNG, JPEG and GeoTIFF; JPEG with a quality, and GeoTIFF packed as Deflate, LZW, JPEG or not at all. GeoJSON is written in WGS 84, as RFC 7946 says, unless it is to keep the coordinate system of the stream. A map from *Draw map* or a chart is written to PDF as **shapes**, sharp at any size, editable in Inkscape or Illustrator and placed on the map in QGIS, with a **layer for each layer** of the map, or as an **SVG** with the same layers for Inkscape; as a choice, a PDF of pixels **JSON** (0.96.1): a list of objects, JSON Lines or the object of the first feature, names with a dot as objects within objects, attributes that hold JSON as JSON, the list under a name of one's own, and the geometry as GeoJSON or WKT if asked. A file named .json with the format left to the file name is still written as GeoJSON. **Google Sheets** (0.96.1): the address of the sheet as the file, written over or added to, in the sheet named in *Sheet*, which is added when it is not there, with the geometry as WKT; through an API connection with a Google service account that the sheet is shared with as an editor. **XML** (0.96.2): an outer element, an element for each feature, an element for each attribute, names with a dot as elements within elements, and the geometry as WKT if asked. **LandXML** (0.96.2): a TIN as surfaces, one for each object of the 3D model, and points with heights as CgPoints, with the coordinate system by its EPSG code. **Schema and TypeScript types** (0.96.2) beside GeoJSON and JSON: name.schema.json and name.d.ts, with each attribute, its type and whether it can be empty. **OpenUSD** (0.96.2) as .usda, or .usdz packed with its textures: each feature an object with its attributes, a layer file for each value of *Layers by* and variants by *Variants by*, such as today and plan, Z up in metres, with the coordinate system and the origin in the metadata of the main file. **Gaussian splats** (0.96.2) as PLY or SPZ, around an origin, y down for PLY and y up for SPZ as viewers expect; a point cloud without splats as a PLY of points. **DXF and DWG** (2010, 2013 and 2018) by acadrust (0.96.3), also from a template drawing whose layers, line types, text styles and blocks are used: a CAD layer, colour and line type by attributes, points as blocks with their attributes filled in from the attributes of the same names and turned by an attribute, and text from an attribute; lines in 3D as 3D polylines and models as 3D faces. **STL, 3MF and STEP for 3D printing and CAD** (0.96.3), in millimetres from the lowest corner at a scale, or as large as a printer plate of 180 mm; 3MF with its colours, STEP as faceted solids with colours that CAD programs read. A **3D walk-through** (0.96.3): a folder with a page that opens in a browser, with the model inside it, to walk in at the height of the eyes, following the ground and stopped by walls, or fly; a click on an object shows its attributes, and the sun and its shadows move with a date and a time. glTF, 3D Tiles and the walk-through can be **packed** by meshoptimizer (EXT_meshopt_compression), with opaque textures as JPEG (0.96.3). **3D Tiles are coarser further away** (0.96.3): tiles of tiles, each with a lighter model of what they hold, fewer triangles and without the smallest objects, shown until one comes near. |
| Make zip file | `ZipWriter` | Packs what the outputs wrote in the run into one zip file, all of them or those named, a Shapefile with its .shx, .dbf and .prj, together with other files and folders, one on each row with a button to choose them, such as a README or styles. In their folders as under the folder of the model, or all at the top. Runs last and needs no connection |
| View | `Viewer` | A place to look at data: connect as many streams as you like to it, from anywhere in the model. Click it, and each connection is shown under the canvas by its number and name in the table, while the map and the 3D view show them all together, such as a model on its terrain; streams in another coordinate system are reprojected for it. A tick box before each stream shows it or hides it on the map and in 3D, and the View keeps the choice. Writes nothing |
| Run model | `ModelRunner` | Runs another model, so that work can be split into models of their own, each easy to follow, and run as a chain. It waits until the other model has run, and what is connected after it runs after that; or it starts the other model by itself with `og` and goes on, with its log in a file beside it. Variables can be given to it, also from this model's own: `year=$(year)`. Connect a stream to *After* to run it after that stream. The lines of the other model come in this log, a step in and under its name, and *Result* has a row for each of its nodes: status, features, files and seconds. A model that would run itself, also by a detour, is stopped |
| Tool | `CustomTool` | A tool of one's own, made of other tools: selected nodes made into one node with a model inside, which a double-click opens. Its *Tool input* and *Tool output* nodes are its ports. Runs once, once for each value of an attribute (with $(value) inside) or a number of times with what comes out going in again (with $(round) inside). Can be unpacked into the nodes again |
| Tool input | `ToolInput` | A port of a tool, inside it: what comes in on the port of that name |
| Tool output | `ToolOutput` | A port of a tool, inside it: what goes out on the port of that name |
| GeoSpatial PDF | `LayeredPdfWriter` | The format *GeoSpatial PDF with layers* of Output. Writes the streams connected to *Layers* as a geospatial PDF where each is a layer that can be turned on and off in the PDF reader. The order and the look of the layers are set as in Draw map; a layer that is not ticked is in the PDF but off when it opens. Features keep their attributes, which the reader can show. Pictures, such as shaded terrain, can be layers. Page size, margin and a title as for PDF |
| QGIS project | `QgisProjectWriter` | The format *QGIS project with its layers* of Output. Writes the streams connected to *Layers* as a QGIS project (.qgz) with the features in a GeoPackage of the same name beside it, points, lines and areas of a stream each a layer of their own, and pictures and rasters as GeoTIFF. The order of the layers and whether each is on are set as in Draw map, and so is the look: fill, line, width and point size in pixels, colours by classes of a number (a graduated renderer) or by a text (categorized, with Other as all other values), point sizes after a number (by area, as an expression), and labels from an attribute or an expression with their size, colour and halo. A background map of tiles, such as OpenStreetMap, can lie under them. Icons are not carried over |
| Web map | `WebMapWriter` | The format *Web map with Leaflet or MapLibre* of Output (0.95). Writes the streams connected to *Layers* as a folder with index.html, to open in a browser or put on a web server, drawn with Leaflet or MapLibre GL, which the page loads from unpkg.com. The layers look as in Draw map: fill, line, width, point size, colours by classes of a number or by a text, sizes after a number, and labels, which do not cover each other unless asked to. A legend turns the layers on and off, a click on a feature shows its attributes, and the map opens zoomed to the data over a background map: OpenStreetMap, CARTO, or one of your own of tiles or WMS (not one that needs a password or a key, which would be written into the page). The features go beside the page in WGS 84 as GeoJSON in script files, which a browser also reads from the disk; with MapLibre a layer of more than 50 000 features, or every layer if asked, goes as PMTiles, which needs a web server. Pictures and rasters are not taken yet |
| Report | `ReportWriter` | Writes a report of what the model made, as a web page (.html, the pictures in it) or a PDF of A4 pages with page numbers: a title, a line under it (the date and time of the run unless another is given), a text first and last of your own (a blank line between paragraphs, `#` for a heading, `-` for a point), and a section for each stream connected to *Sections*, in the order they were connected, under the name of the tool it comes from. Maps, charts and 3D scenes are pictures; other streams are tables of their attributes, at most the rows given. The PDF is set in Helvetica, which has the letters of Western Europe. The tables can have one of a few colours (plain, sea, forest, sand, graphite), in the web page and the PDF, and in the web page a click on the heading of a column sorts its rows by it, a second the other way, numbers as numbers and words in Swedish order |
| Slides | `SlideWriter` | The formats *PowerPoint slides* and *LibreOffice Impress slides* of Output. Writes the pictures connected to *Pictures*, from Draw map, Draw chart, Render 3D scene and others, as a .pptx or an .odp file: a slide for each, as large as fits, with the name of the tool it comes from as its title. A first slide with a title and a line under it, wide (16:9) or standard (4:3) slides, and a background colour |
| Output to PostGIS | `PostgisWriter` | The format *PostGIS table* of Output, also to SQL Server, where the table gets a geometry column with a spatial index and the key chosen as its primary key (a key that is not a whole number gets a unique index instead). A window as for the input chooses the connection, and the schema and table, new or one that is there. The form sets what happens to a table that is there (replace or add to it), the geometry type (as the features are, or Point, MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon, or no geometry), the coordinate system to reproject to, the name of the geometry column, and the **primary key** of a new table: a new column of numbers by the name you give (ogc_fid from the start), or an attribute whose values are all different and none empty, whole numbers or text. Names are written in lower case with spaces as `_`. The table gets a spatial index, and is written in one transaction: if something fails, nothing is written. *If the table is there* can also **empty it and fill it again**, in one transaction: the table keeps its indexes, rights and the views on it. *Transaction*: all or nothing, or **in parts**, committed every so many rows, for very large writes. **SQL before** and **SQL after** run in the same transaction as the write, with `{table}` for the table written. *New statistics* runs ANALYZE (UPDATE STATISTICS on SQL Server) afterwards. Under *Table* the names in the database are shown, with a warning for names over 63 characters. A node with the server and password written in it, as models from before 0.63 have, gets **Save as a connection**, which moves them to the settings (0.95.3). The seldom changed settings wait under *More*. If the table is there: replace it, empty it and fill it again, add to it, or **update the rows by a key**, such as an id, and add the new ones, and as a choice delete the rows that are not in the stream, all in one transaction **Comments** (0.96.2) on the table and on columns, kept in the database (COMMENT ON), where other programs show them. |

Attributes:

| Tool | In files | Does |
| --- | --- | --- |
| Calculate statistics | `StatisticsCalculator` | Count, sum, min, max, mean, median and the percentiles you ask for, such as 10 and 90, for the whole stream or per group |
| Check attributes | `AttributeValidator` | Checks the values of attributes, a row for each: that it has a value, its type (whole number, number, text, date), its longest length, its smallest and largest value, and a list of values it may have. Passed, or Failed with what is wrong in an attribute |
| Count | `Counter` | Numbers the features in the order they come, from 1 or a number you choose, in an attribute. Can start again for each group |
| Random number | `RandomNumber` | Gives each feature a random number between a smallest and a largest, with the decimals you choose; with no decimals, a whole number that can be either end. The same seed gives the same numbers |
| Reproject coordinate attributes | `CoordinateReprojector` | Reprojects an x and a y kept in attributes, such as columns of a spreadsheet, from one coordinate system to another, into new attributes. The geometry is left as it is |
| Classify by range | `RangeMapper` | Gives each feature a value by the range its number falls in: 1–100 gives A, 101–200 gives B, in an attribute you name. The ranges are given in rows of from, to and value, or made from the data as equal intervals or with as many features in each. A value in no range gets a text you choose, or nothing |
| Map values | `ValueMapper` | Looks up each value of an attribute in a list and writes what it becomes, such as 1 to Health centre, in the attribute or a new one. *Use the values in the data* fills in the list after a run. Values not in the list are kept, left empty or given a text. A result of only numbers is a number |
| Concatenate attributes | `StringConcatenator` | Joins several attributes into one, with a separator if you want one. A fixed text is written among them in single quotes, `'0', kod` or `name, ', ', town`, and may hold commas and spaces. The fixed texts can be **separators of their own**, so that different ones go between different attributes: `code, ' - ', name, ', ', town` gives *12 - Main street, Skövde*, and a separator next to an empty value is left out |
| Create attribute | `AttributeCreator` | Calculates an attribute with an expression, as the field calculator of QGIS. Under the expression stand the attributes to click in, the value it gives for the first feature, and a list of the functions and variables with a line of help each |
| Extract substring | `SubstringExtractor` | Takes the first or last characters of a text, or a number of characters from a position |
| Filter by value | `ValueFilter` | An output for each value of an attribute that you list, for example A, B and C, and Other for the rest. Values can be ticked in the list and removed all at once, or kept while the others go |

```
CASE WHEN height > 20 THEN 'high' WHEN height > 10 THEN 'middle' ELSE 'low' END

regexp_substr(address, '(\d{3} ?\d{2})')
date_add('$(departure)', 15 * ($id - 1), 'minutes')
```

- **Operators**: `+ - * /`, `//` whole division, `%` the rest, `^` a power (`-2 ^ 2` is −4),
  `||` joins text; `= <> < > <= >=`, `AND`, `OR`, `NOT`, `IS NULL`, `IN (…)`, `LIKE` and
  `ILIKE`; `CASE WHEN … THEN … ELSE … END`.
- **Variables** of the geometry: `$area`, `$length`, `$perimeter`, `$x`, `$y` and `$z` of a
  point, `$xmin`, `$ymin`, `$xmax`, `$ymax`, `$num_points`, and `$id`, the number of the
  feature in the stream from 1.
- **Numbers**: `round`, `abs`, `sqrt`, `floor`, `ceil`, `min`, `max`, `clamp`, `power`, `exp`,
  `ln`, `log10`, `log`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `pi`, `radians`,
  `degrees`.
- **Text**: `upper`, `lower`, `initcap`, `length`, `trim`, `substr`, `left`, `right`,
  `replace`, `lpad`, `rpad`, `concat`, `strpos`, `starts_with`, `ends_with`, and regular
  expressions with `regexp_replace`, `regexp_match` and `regexp_substr`.
- **Times**: `now`, `format_time`, `epoch`, `year`, `month`, `day`, `hour`, `minute`,
  `second`, `day_of_week` (1 Monday), `week` (as in Sweden), `date_add` and `date_diff`.
- **Others**: `if`, `coalesce`, `nullif`, `to_int`, `to_real`, `to_string`.

## The model format

A model is a JSON file. Paths start from the folder the file is in. `x` and `y` are the
position of the node on the canvas and do not affect the run.

```json
{
  "format": "ographis/1",
  "name": "Build test",
  "nodes": [
    { "id": "in", "type": "Reader", "name": "Subregions", "params": { "path": "subregions.gpkg" } },
    { "id": "sweref", "type": "Reprojector", "params": { "crs": "EPSG:3006" } },
    { "id": "out", "type": "Writer", "params": { "path": "out/subregions_sweref.shp" } }
  ],
  "edges": [
    { "from": ["in", "Output"], "to": ["sweref", "Input"] },
    { "from": ["sweref", "Reprojected"], "to": ["out", "Input"] }
  ]
}
```

A node can have a `comment`. Next to `nodes` and `edges` the file can hold `groups`, the
named boxes on the canvas, and `notes`, the free-standing notes. Neither affects the run.

```json
"groups": [{ "name": "Input", "x": 0, "y": 20, "w": 250, "h": 430, "color": "yellow", "locked": true }],
```

The colour is one of grey (empty), yellow, orange, red, pink, purple, blue, teal, green and
brown, or a colour of its own as `#8a2be2`.

```
"notes": [{ "text": "The stops are made up.", "x": 290, "y": 480 }]
```

A node with `"disabled": true` does not run. `navigator` holds the ids of the inputs and
outputs in the order they have been put in the navigator. An output can be told the format
and how to write single attributes:

```json
{ "id": "out", "type": "Writer", "params": { "path": "out/result", "format": "shp",
  "fields": { "name": { "length": 20 }, "code": { "type": "integer" }, "share": { "decimals": 2 } } } }
```

An input of a folder gives the folder as `path` and a filter as `pattern`. Several layers
are given as a list, and `*` stands for all of them.

```json
{ "id": "stops", "type": "Reader", "params": { "path": "stops", "pattern": "*.csv", "filename_attr": "file" } },
{ "id": "two", "type": "Reader", "params": { "path": "areas.gpkg", "layer": ["north", "south"] } },
{ "id": "web", "type": "Reader", "params": { "path": "https://example.org/open/roads.zip", "limit": "1000" } },
{ "id": "grid", "type": "Reader", "params": { "path": "heights.tif", "raster_as": "cells" } },
{ "id": "dem", "type": "Reader", "params": { "path": "terrain.tif", "raster_as": "grid", "cell_size": "10" } }
```

The look of a workbook, the rows of Manage attributes and the values of Filter by value:

```json
{ "id": "xl", "type": "Writer", "params": { "path": "out/towns.xlsx", "font": "Arial", "colors": "blue", "freeze": "false" } },
{ "id": "tidy", "type": "AttributeManager", "params": {
  "attributes": [{ "name": "pop", "action": "rename", "to": "population" }, { "name": "x", "action": "remove" }, { "name": "name" }],
  "others": "keep",
  "create": [{ "name": "county", "value": "'Västra Götaland'" }] } },
{ "id": "by_class", "type": "ValueFilter", "params": { "attribute": "class", "values": ["A", "B", "C"] } }
```

A connection from a Filter by value names the value as its port: `"from": ["by_class", "B"]`.
The order a user has given the ports of a node is kept among its parameters, as
`"_port_order": { "in": ["Clippee", "Clipper"] }`. The run does not read it.
Manage attributes from before 0.53, with `keep`, `remove` and `rename`, still runs, and is
turned into the list when it is opened in the program after a run.

Files with the earlier format name `flodesbanken/1` are still read, and are saved as
`ographis/1`.
